## 결론 요약

**추첨 자체에는 패턴이 없다.** 번호별 균등성, 홀짝, 합계, 연속번호, 회차 간 독립성, 시대별 변화, 주기성, 재출현 간격, 조합 중복 — 10개 검정이 모두 무작위 가설과 일치했다(최소 p = 0.287). 최다 34번(186회)과 최소 9번(136회)의 차이도 다중비교 보정 후 p = 0.92.

**그러나 1등 당첨금은 영향을 받는다.** 당첨금은 정해진 몫을 당첨자끼리 나눈 값이라, 같은 조합을 몇 명이 골랐는지가 금액을 정한다. 1등 당첨자 수의 분산/평균 비 = 1.90 (순수 무작위면 1.00).

| 조합 특성 | 사람 선호도 | p값 |
|---|---|---|
| 번호 합계 110 이하 | 1.092 | 6.2e−5 |
| 번호 합계 171 이상 | 0.894 | 1.9e−5 |
| 최대−최소 폭 20 이하 | 1.131 | 0.0011 |
| 연속번호 포함 | 0.959 | 0.0021 |
| 용지 인접칸 3쌍 이상 | 1.096 | 0.0074 |
| 번호 크기 × 선호도 상관 | r = −0.510 | 1.0e−4 |

**무더기 1등은 용지에서 나온다.** 1등 30명 초과 회차는 순수 무작위 기대치의 119배. 1152회 `30·31·32 / 35·36·37`처럼 용지 위에서 도형이 되는 조합이 원인이며, 이 효과는 실제 용지 배열인 **7칸 격자에서만** 잡히고 5·6·9칸에서는 사라진다.

**검출 한계.** 3D 시뮬레이션 검출력 분석 결과, 1,241회차로 배제할 수 있는 건 **편향 15% 이상**뿐이다(검출력 97%). 5% 편향은 검출력 24%로, 있어도 놓칠 가능성이 더 크다. 공식 볼 무게 허용오차 ±5%가 만드는 약 7.3% 편향은 24년치로 절반 이상 놓친다.

> **당첨 확률을 높이는 방법은 없습니다.** 모든 조합이 1/8,145,060로 동일합니다. 당첨금 지급률이 판매액의 50%로 고정돼 있어 기대수익률은 어떤 조합에서도 마이너스입니다. 도박 문제 상담: 국번 없이 **1336**.

## 사용법

### 데이터 갱신 (매주)

```bash
node scripts/update_lotto.mjs
```

새 회차만 받아 `data/` 에 추가합니다. 전체를 다시 받으려면 `--full`.

### 메뉴 갱신

```bash
node scripts/inject_nav.mjs
```

`assets/nav.css` 를 고치거나 페이지를 다시 생성한 뒤 실행하면, 세 페이지 상단 메뉴가 일괄 갱신됩니다. 여러 번 실행해도 중복되지 않습니다.

### 시뮬레이터 검증

```bash
node scripts/venus_check.mjs 120000    # 비너스 사양 균등성 (120k 회차)
node scripts/null_check.mjs 20000      # 정밀 설정 중립성
node scripts/power.mjs                 # 편향 검출력 시나리오
```

Node 18+ 필요 (내장 `fetch` 사용). 외부 의존성 없음.

## 데이터 출처와 주의사항

- 동행복권 공식 추첨결과 API: `dhlottery.co.kr/lt645/selectPstLt645InfoNew.do`
- 널리 알려진 구 API(`common.do?method=getLottoNumber`)는 사이트 개편으로 **폐기**되어 홈으로 리다이렉트됩니다.
- API의 `rlvtEpsdSumNtslAmt` 필드는 판매액이 아니라 **총 당첨금**입니다(465회차 이후 등수별 지급액 합계와 정확히 일치). 실제 판매액은 이 API에 없습니다.
- 선호도는 1등 당첨자 수에서 역산한 간접 지표이며, 실제 구매 조합 데이터가 아닙니다. 노출량은 앞뒤 회차 기준으로 잡아 당첨번호와 독립시켰습니다.
